# /change-request

For a requirement that **changed**. For a genuinely new one, use
`/new-requirement`.

**Loads**
- `.claude/skills/contract-authoring.md`
- `.claude/skills/plan-file-format.md`
- `.claude/skills/requirement-decomposition.md`
- `.claude/skills/error-registry.md`

**Delegates to:** `.claude/agents/test-author.md` (regeneration)
**Calls:** `.claude/scripts/trace_impact.py`,
`.claude/scripts/id_allocator.py`, `.claude/scripts/regen_indexes.py`,
`.claude/scripts/check_links.py`

---

## Input

`$ARGUMENTS` — a `REQ-###` and what changed. If the requirement is unclear, ask
rather than guessing which one is meant.

---

## Steps

**1. Trace forward.** `trace_impact.py` from the requirement →
stories → endpoints → contracts → tests.

**2. Produce the impact report.** Affected stories, endpoints (with current
status), contracts, test files, error codes. Flag endpoints already complete —
those are the expensive ones.

**3. Classify every contract change.**

*Additive* — new optional request field, new response field, new endpoint,
relaxed validation, new optional query parameter.

*Breaking* — field removed or renamed, type changed, validation tightened,
status code changed, enum value removed, required field added, error code
removed or redefined, pagination sort column changed, default behaviour changed.

**When unsure, classify as breaking.** Being wrong that way costs a
conversation; the other way breaks a frontend.

**4. Stop for approval — always.**
Present the impact report and the classification. For each breaking change ask:
**version the endpoint, or coordinate with the consumer?**

**5. On approval, apply in this order:**

- `CR-###` written to `plan/changes/`
- Requirement entry updated with a changelog line — verbatim new text, date,
  reason
- Contracts updated
- Error codes added or deprecated (never deleted, never reused)
- Schemas updated
- Tests regenerated by `test-author` from the updated contract, walking the
  same edge-case checklist so coverage cannot narrow
- Affected endpoints set to `needs-rebuild`
- Affected stories marked incomplete
- `DEC-###` logged for every breaking-change decision, with reasoning

**6. Run** `regen_indexes.py`, then `check_links.py`. Report.

---

## Scope removal

A requirement being dropped is also a change request. Mark it **deferred** or
**removed** with a date and reason — never delete it.

Endpoints already built against it get an explicit decision: leave, deprecate,
or remove. Logged as a `DEC-###`.

## Output

| File | Contents |
|---|---|
| `plan/changes/CR-###.md` | What changed, impact, classification, decision |
| `plan/requirements/inventory.md` | Changelog line on the requirement |
| `contracts/...` | Updated |
| `plan/decisions.md` | `DEC-###` for breaking-change decisions |
| `plan/endpoints/EP-###.md` | Marked `needs-rebuild` |
| `tests/...` | Regenerated |

---

## Do not

- Apply anything before approval
- Classify a change as additive when unsure
- Delete a requirement or an error code
- Renumber anything
- Rebuild endpoints in this command — that is `/build-endpoint`
- Re-run decomposition on a revised document; diff and raise change requests
